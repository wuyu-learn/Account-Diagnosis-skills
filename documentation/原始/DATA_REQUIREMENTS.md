# 账户诊断卡片数据要求汇总

> 本文从新版卡片代码中提取数据相关信息，仅记录数据源、取数方式、统计口径、核心字段及数据规则，不包含视觉样式和交互说明。

## 一、通用约定

### 1. dataMode

- `inline`：卡片数据随卡片结果直接返回，前端直接渲染。
- `deferred`：先返回 `data.request`，前端再调用 `POST /api/account/card/{cardId}` 取数。
- deferred 请求至少包含 `account_type`、`card_id`、`view_mode`、`dimension`、`period` 等必要参数。
- deferred 取数失败或超时，当前规则为整卡隐藏。

### 2. 通用数据状态

- `available`：数据正常。
- `zero`：数据正常，数值为 0。
- `empty`：当前统计范围内无数据。
- `unavailable`：数据缺失或暂不可用，不得使用 `0` 代替。
- 涉及今日基金收益时，可按业务返回 `estimated`、`mixed`、`real` 等更新状态。

### 3. 通用口径

- 金额默认以元为单位，收益金额带正负号。
- 账户层按产品汇总；除明确标注“穿透”的模块外，不穿透底层资产。
- 实际收益为 0、无数据和数据未更新必须区分。
- 净值、收益和持仓数据以登记确认或管理人披露结果为准。

## 三、逐卡数据要求

### ACC-01 账户总资产卡

- 统计账户总资产及货币、基金、投顾、组合、专户等资产构成。
- 核心字段：总资产、今日收益、持仓收益、累计收益、账户类型资产及占比、资产来源。
- 资产来源区分汇添富资产和外部导入资产。
- 仅基金支持盘中预估；今日收益需区分全预估、更新中和更新完成。
- 非基金账户类型不展示预估信息。

### ACC-02 基金账户详情卡

- 统计普通公募基金、QDII 等基金产品，不包含货币基金、投顾和专户。
- 入参口径：`scope=fund`。
- 核心字段：总市值、今日收益、持有收益、累计收益、基金持仓列表。
- 单只基金字段：基金名称、代码、资产、今日收益、持有收益及持有收益率。
- 今日可先使用预估值，盘后以确认净值更新。

### ACC-03 基金持有详情卡

- 入参：`fund_code`。
- 统计单只基金在当前账户内的持有口径，不等同于基金产品自身表现。
- 核心字段：持有资产、成本、份额、今日收益、累计收益、交易记录、收益走势。
- 收益走势支持收益率、累计收益和成本单价等视角。
- 交易记录为只读数据。

### ACC-04 投顾账户详情卡

- 统计账户内投顾组合，不穿透底层基金。
- 核心字段：总资产、今日收益、持有收益、累计收益、投顾组合列表。
- 头部三项收益仅展示金额，不展示收益率。
- 页面不使用预估收益或预估标签。
- 组合列表字段：组合名称、代码、资产、今日收益、持有收益及持有收益率。

### ACC-05 投顾组合详情卡

- 入参：`scope=combo`、`combo_id`。
- 核心字段：组合资产、今日收益、持有收益、累计收益、底层基金持仓。
- 底层基金市值合计应等于组合市值。
- 组合层不展示份额；页面不使用预估表达。
- 业绩走势采用份额归一 TWR，与管理人披露的业绩比较基准对比。
- 收益统计金额采用客户资金口径；资产配置可穿透至股票、债券、现金等大类资产。
- 其他数据包括调仓状态、配置偏离、投顾报告及主理人披露观点。

### ACC-06 投顾调仓记录卡

- 入参：`combo_id`，默认查询近 1 年。
- 数据粒度仅到调仓日期和管理人披露说明，不包含具体买卖标的或金额。
- 核心字段：组合代码、组合名称、调仓次数、调仓日期、披露原文、披露时间、来源。
- 调仓记录按日期倒序。
- 需区分无调仓、说明未披露和数据不可用。
- 未披露调仓原因时不得生成或补写内容。

### ACC-07 货币账户详情卡

- 入参口径：`scope=money`。
- 统计账户内货币基金，不包含普通基金、投顾和专户。
- 核心字段：总资产、今日收益、持有收益、累计收益、货币基金持仓列表。
- 单只货币基金字段：资产、今日收益、万份收益、七日年化收益率。
- 页面不使用预估收益或预估标签，今日收益以登记确认结果为准。
- 周末和节假日存在实际收益时正常计入。

### ACC-08 货币持有详情卡

- 入参：`money_code`。
- 统计单只货币基金持有数据。
- 核心字段：持有市值、持有份额、今日收益、累计收益、万份收益、七日年化收益率及对应日期。
- 页面不使用预估表达。
- 万份收益和七日年化以基金管理人披露结果为准。

### ACC-09 专户账户详情卡

- 入参口径：`scope=separate`。
- 统计账户内专户或资管类产品，仅展示产品层数据，不穿透底层。
- 核心字段：总市值、净值日期、今日收益、持有收益、累计收益、专户产品列表。
- 头部收益三栏只展示金额，不展示收益率。
- 页面不使用预估表达。

### ACC-10 专户持有详情卡

- 入参：专户产品标识，`get_holding_detail` 使用 `separate` 口径。
- 仅展示管理人披露的产品层持有信息，不穿透底层。
- 核心字段：产品名称、代码、持有市值、持有份额、今日收益、持有收益、累计收益、最新净值及净值日期。
- 页面不使用预估表达，也不返回或展示收益率字段。

### ACC-11 持仓明细卡

- 支持按产品和按基金穿透两种统计视角。
- 核心字段：产品类型、产品名称、代码、资产、市值占比、收益、份额、净值及相关日期。
- 支持基金、投顾、组合、专户、货币等类型，不同类型展示深度不同。
- 专户仅汇总；投顾和组合是否穿透由视角与披露权限决定。

### ACC-12 资产结构卡

- 支持资产类型、基金类型、行业主题和市场区域等维度。
- 核心字段：维度、分类名称、资产金额、资产占比、明细列表。
- 资产类型穿透到股票、债券、现金等大类资产。
- 只陈述资产分布，不产生配置高低判断。

### ACC-13 账户收益总览卡

- 累计区固定使用建仓以来口径，区间区随周期切换。
- 核心字段：累计收益、累计收益率、今日收益、预估收益、已更新收益、区间收益、超额收益、最大回撤。
- 累计收益可拆分为预估收益和已更新收益。
- 今日需区分全预估、更新中和更新完成。
- 更新中状态不展示今日收益率。
- 超额收益为账户区间收益减去基准区间收益。

### ACC-14 收益明细日历卡

- 支持日、月、年三种粒度。
- 日粒度展示当月，月粒度展示当年，年粒度展示历年。
- 核心字段：周期标识、收益金额、收益率、周期累计、数据状态、产品贡献。
- 日加总等于月累计，月加总等于年累计，各级数据需形成对账闭环。
- 非交易日有实际收益时仍正常展示，货币基金节假日收益不得因非交易日被过滤。
- 产品贡献随当前选中周期变化，按产品统计且不穿透。

### ACC-15 收益归因卡

- 数据源当前代码为 `get_return_attribution`。
- 支持今日、昨日、本月、本年和历史以来等周期。
- 按产品拆分盈利贡献和亏损拖累，不穿透底层资产。
- 核心字段：总收益、总盈利、总亏损、盈利 Top 列表、拖累 Top 列表、贡献金额及占比。
- 盈利按金额降序；拖累按亏损绝对金额降序。
- 收益方向使用接口原值，正值和负值不得反转。

### ACC-16 收益构成卡

- 入参口径：`group_by=account_type`。
- 按货币、基金、投顾、组合、专户等账户来源汇总收益。
- 核心字段：周期、总收益、账户类型收益金额、贡献占比、收益序列。
- 投顾与自购基金对比使用份额归一 TWR，避免申赎时点影响。
- 仅做同口径事实对比。

### ACC-17 区间收益归因卡

- 入参：`scope=fund`、`mode=interval` 及区间参数。
- 统计单只基金指定区间的收益来源与波动。
- 核心字段：区间收益金额、资金加权收益率、最大成本收益率、最大涨幅、最大回撤、收益序列、份额归因。
- 资金加权口径包含申赎时点影响；最大成本口径按成本法计算。
- 份额归因按先进先出拆分期初持仓和区间新增份额。

### ACC-18 自选基金估值卡

- 统计自选基金当日估值、净值和连涨跌状态。
- 核心字段：基金名称、代码、当日涨跌幅、估算或确认净值、净值日期、连续涨跌天数、更新状态。
- 不返回或展示持有、未持有标签及筛选。
- 不展示关联板块列。
- 盘中使用估值；收盘确认后切换为已更新净值。

### ACC-19 产品份额明细卡

- 入参口径：`scope=product`。
- 统计单个产品的总份额和下层份额明细。
- 核心字段：产品名称、产品代码、总份额、资产、今日收益、持有收益、持有收益率、份额列表。
- 今日基金收益可区分盘中预估和盘后确认。
- 具体字段及对账规则仍需补充正式接口契约。

## 四、待确认项

1. ACC-04 和 ACC-13 的数据源未在当前卡片 HTML 中明确写出，本文按现有需求上下文暂列，需与接口负责人确认。
2. ACC-15 当前代码使用 `get_return_attribution`，与部分历史需求中使用 `get_return_performance` 的描述不一致，需统一。
3. ACC-19 已加入页面清单并标记为 `inline`，但旧版目录的逐卡 dataMode 表尚未补充。
4. “货币基金收益不得为负”建议作为异常校验规则，而不是无条件修改接口原值。
5. 各卡字段命名需最终统一为 snake_case 或 camelCase，避免同一概念出现多套命名。
