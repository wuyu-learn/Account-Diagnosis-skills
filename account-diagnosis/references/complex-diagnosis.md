## 适用条件

只在 `taskComplexity = complex` 时使用。完整读取 `references/mcp-evidence.md`。

复杂诊断只生成 Summary、Conclusion 和 followUp。业务 Section、卡片、顺序和固定文案由代码生成。

遵守根 `SKILL.md` 的账户顾问工作立场：帮助用户看清账户，不做数据播报、产品销售或替用户决策。

## 输入

复杂诊断任务必须同时读取：

- 上游不可改写的 `originalQuery`；
- 只读的账户计划，包括复杂度原因、账户意图和卡片计划；
- 已完成质量检查的本次 MCP 证据，包括来源、状态、账户范围、日期或周期、可信对象标识和事实；
- 数据缺失、估算值、口径冲突和不可关联标记。

不得使用 deferred 卡片未来可能加载的数据，也不得把 MCP 原始响应直接写成诊断结论。

## 诊断路径

根据 `originalQuery` 和账户计划在复杂任务内部选择路径，不新增 Planner 字段。

### 完整账户诊断

适用于“我的账户怎么样”“给账户做一次体检”等整体问题。默认检查：

```text
账户范围和规模
→ 产品结构
→ 资产、地区和行业结构
→ 收益、超额收益和最大回撤
→ 主要贡献和拖累
```

通常需要 `queryAssetsTotal`、`queryHoldingDetail`、`queryAssetClassify`、`queryProfitAnalyze` 和 `queryProfitAttribution`。这是完整诊断的证据组合，不是所有 complex 任务的固定调用清单。

### 关系型诊断

适用于“哪些重仓产品是主要拖累”“持仓结构为什么导致收益不好”等问题。

只取得建立目标关系所需的最少证据。例如：

| 目标关系 | 最少证据 |
| --- | --- |
| 重仓产品是否为主要拖累 | 同范围、同周期的持仓权重和产品归因 |
| 主要行业暴露是否造成拖累 | 同范围、同周期的行业结构和行业归因 |
| 跑输基准的原因 | 收益/基准表现和同周期归因 |

complex 表示需要诊断关系和优先级，不表示无条件调用全部 MCP。

## 复杂诊断注入块

MCP 返回并完成数据质量检查后、生成 Summary/Conclusion 前，按以下顺序执行：

```text
1. 明确账户范围、数据日期和诊断周期
2. 区分可用、部分可用、不可用、真实零值和估算值
3. 从单品清单转换为组合结构
4. 评价绝对收益、相对基准表现和最大回撤
5. 定位主要贡献和主要拖累
6. 检查结构与收益来源能否建立关系
7. 确定一至三个关注点及优先级
8. 明确当前数据和能力边界
```

账户诊断关注“这些产品组合在一起意味着什么”，不是逐只评价产品。

只有账户范围、诊断周期和对象标识一致时才能建立跨维度关系。任何条件不一致时，只能并列陈述事实并说明关系无法建立。

没有 KYC、客户目标、投资期限和风险承受能力时，不判断账户是否适合用户、配置是否合理，也不给出买卖或调仓结论。

## 关系判断与优先级

### 收益质量

| 收益 | 超额收益 | 诊断表达 |
| --- | --- | --- |
| 正 | 正 | 赚钱且跑赢基准 |
| 正 | 负 | 赚钱，但弱于基准 |
| 负 | 正 | 亏损，但相对基准更抗跌 |
| 负 | 负 | 亏损且跑输基准 |

没有正式阈值或可比标准时，只报告最大回撤，不判断回撤过大。

### 结构与归因

| 结构事实 | 归因事实 | 可形成的诊断 |
| --- | --- | --- |
| 头部持仓 | 同一产品为主要拖累 | 主要拖累与头部持仓重合，优先关注 |
| 头部持仓 | 同一产品为主要贡献 | 收益较依赖头部持仓 |
| 主要行业/地区暴露 | 同维度为主要拖累 | 结构暴露与本期拖累方向一致 |
| 主要行业/地区暴露 | 同维度为主要贡献 | 收益较依赖该结构暴露 |
| 结构集中 | 没有对应负归因 | 只能认定集中，不能认定已经造成问题 |

### 优先级

```text
第一：主要拖累与头部持仓或主要暴露重合
第二：跑输基准或发生回撤，但原因未完全定位
第三：收益依赖少数产品或单一暴露，尚未形成拖累
第四：只有结构特征，尚未发现实际收益影响
```

复杂任务必须产生以下两种结果之一：

```text
证据充分
→ 至少形成一个跨维度关系判断
→ 保留最重要的一至三个发现并排序

证据不足
→ 说明哪些局部事实成立
→ 明确哪些关系无法建立以及原因
```

不能只罗列总资产、持仓、收益和归因数字后称为综合诊断。

## 输出

只输出：

```json
{
  "summary": {
    "title": "账户诊断摘要",
    "narrative": "账户范围和周期 + 核心表现 + 第一优先级发现及证据。"
  },
  "conclusion": {
    "title": "综合结论",
    "narrative": "跨维度关系判断 + 关注点优先级 + 数据或能力边界。"
  },
  "followUp": []
}
```

- Summary 回答“本次覆盖什么、发生了什么、最重要的发现是什么”；
- Conclusion 回答“这些事实组合在一起意味着什么、先关注什么、当前不能判断什么”；
- Conclusion 不重复数字清单，不引入新事实；
- 表达清楚、克制、有依据，既不制造焦虑，也不回避问题；
- followUp 只提供可选的继续诊断方向；
- 不输出业务 Section、卡片、最终 v2.2 字段、MCP 原始数据或投资建议。

## 示例

### 完整账户诊断

```text
已校验证据：
账户收益率 -2.8%，超额收益 -3.8%；
产品 A 是第一大持仓；
同范围、同周期内产品 A 也是第一大拖累。

summary：本次诊断显示，账户在该周期亏损 2.8%，并跑输基准 3.8 个百分点。第一大持仓产品 A 同时是第一大拖累，是当前最需要关注的因素。

conclusion：账户本期表现偏弱，且主要拖累与头部持仓重合，产品 A 对账户损益的影响优先级最高。由于缺少用户目标和风险承受能力，本次不判断该持仓是否适合用户，也不形成调仓建议。
```

### 关系型诊断证据不足

```text
用户问题：持仓结构为什么导致收益不好？
已校验证据：取得产品持仓权重和账户收益，但归因数据不可用。

summary：当前可以确认账户收益表现和头部持仓结构，但缺少同周期归因，无法确认哪些持仓造成了本期拖累。

conclusion：现有证据只能说明账户存在头部持仓，不能认定该结构已经导致收益不佳。需要取得同范围、同周期的归因数据后才能建立两者关系。
```

## 数据不足

- 部分可用：只形成有证据的局部诊断，Conclusion 说明缺失维度和无法建立的关系；
- 核心数据不可用：Summary 说明无法取得所需证据，Conclusion 明确不能形成账户级判断；
- 不使用 deferred 卡片未来可能加载的数据补写诊断；
- 不用空泛安慰替代证据，也不因数据缺失删除已经规划的卡片。
