# 我的账户诊断理念与逻辑

“我的账户诊断”基于现有账户数据，先检查数据质量，再分析产品、资产、地区和行业结构，评价账户的收益、超额收益和回撤表现，最后通过产品归因定位主要贡献和拖累。

这句话描述的是完整诊断能力，不代表每次问账户都要执行全部步骤。实际执行应由用户当前问题决定：**先识别诊断场景，再调用能够回答该问题的最少 MCP，最后只在已经取得证据的范围内输出诊断。**

## 1. 核心逻辑

```text
用户问题
→ 识别本次诊断场景
→ 明确本次必须回答的问题
→ 选择最少必要的 MCP
→ 检查本次返回数据的质量和口径
→ 用固定规则计算诊断指标
→ 输出事实、判断和边界
→ 用户继续追问时再增加新的 MCP
```

核心原则：

1. 不是“为了做账户诊断，把所有 MCP 调一遍”，而是“为了回答当前问题，取得最少且足够的证据”。
2. 单点问题只做局部诊断，不把局部结果扩大为完整账户结论。
3. 复合问题合并各场景所需的 MCP，去重后调用，不补调无关数据。
4. 只有用户明确要求“全面诊断、账户体检、整体分析”时，才执行完整诊断链路。
5. 数据质量检查不是一个额外取数场景，而是每次 MCP 返回后都必须执行的前置校验。

## 2. MCP 与卡片的关系

MCP 和卡片是两条独立的数据链：

```text
MCP → 为 summary 和 conclusion 提供诊断证据
卡片 → 前端组件自行取数并展示
```

因此：

- 不能根据选中了几张卡片，决定调用几个 MCP；
- 不能把 MCP 返回的金额、比例、收益率或归因结果填进卡片；
- 卡片固定使用 `deferred`，`data` 保持空对象；
- 业务 section 只说明卡片展示什么，不重复写 MCP 诊断数据；
- 即使 MCP 失败，已经根据用户意图选中的卡片仍可以输出，但 summary 和 conclusion 不能补造结论。

卡片只输出组件信封：

```json
{
  "cardId": "ACC-XX",
  "dataMode": "deferred",
  "data": {}
}
```

## 3. 场景与最小 MCP

### 3.1 单一场景

| 诊断场景 | 典型问法 | 本次要回答的问题 | 最小 MCP | 对应诊断输出 |
| --- | --- | --- | --- | --- |
| 账户总览 | “我的账户有多少钱”“账户整体怎么样” | 账户规模、账户构成、持仓数量 | `queryAssetsTotal` | 总资产、主要账户构成、持仓数量及数据时点 |
| 产品持仓 | “我买了什么”“产品是不是太集中” | 持有哪些产品、头部产品占比 | `queryHoldingDetail` | 产品数量、最大持仓、Top 3/Top 5 占比、产品集中度 |
| 资产结构 | “资产怎么配置的”“地区和行业集中吗” | 资产、地区、行业和风格暴露 | `queryAssetClassify` | 各维度主要分布、最大项、Top N 占比和集中度 |
| 收益总览 | “今年赚了多少”“累计收益怎么样” | 指定周期赚亏金额及收益率 | `queryProfitAnalyzeSum` | 收益金额、收益率、实际/估算状态 |
| 收益与风险 | “跑赢大盘了吗”“收益和回撤怎么样” | 区间收益、超额收益、最大回撤 | `queryProfitAnalyze` | 区间收益、基准、超额收益、最大回撤和走势特征 |
| 收益时段 | “哪个月亏得最多”“按月看收益” | 收益在日、月、年上的分布 | `queryProfitCalendar` | 最好/最差时段、收益分布及连续赚亏情况 |
| 收益归因 | “谁贡献了收益”“哪些产品在拖累” | 收益来自哪里、亏损由谁造成 | `queryProfitAttribution` | 主要贡献项、主要拖累项、损益集中情况 |
| 今日表现 | “今天账户表现怎么样” | 今日收益和今日超额表现 | `queryAssetIndex` | 今日实际/估算收益、今日收益率和超额表现 |
| 今日提醒 | “今天有哪些持仓要关注” | 当前持仓提醒 | `queryHoldingSignal` | MCP 已返回的提醒事实，不扩展为买卖建议 |
| 产品份额 | “这只产品有多少份” | 指定产品的份额明细 | `queryShareDetail` | 指定产品份额及接口实际返回的相关字段 |

这里的“最小 MCP”是默认选择，不是固定绑定。只有当前问题确实需要第二类证据时，才增加调用。

### 3.2 需要增加 MCP 的条件

| 当前场景 | 用户增加的问题 | 增加的 MCP | 原因 |
| --- | --- | --- | --- |
| 收益总览 | “跑赢基准了吗、回撤多大” | `queryProfitAnalyze` | 收益总览不能回答超额收益和最大回撤 |
| 收益与风险 | “为什么会这样” | `queryProfitAttribution` | 收益结果不能直接说明贡献和拖累来源 |
| 收益归因 | “拖累产品在账户里占多大” | `queryHoldingDetail` | 需要把归因结果和当前持仓权重关联 |
| 产品持仓 | “这些产品实际投向哪些资产、地区和行业” | `queryAssetClassify` | 产品列表不能替代资产分类数据 |
| 资产结构 | “具体是哪几只产品造成集中” | `queryHoldingDetail` | 分类集中度不能直接定位具体持仓产品 |
| 今日表现 | “今天哪些持仓需要关注” | `queryHoldingSignal` | 今日收益和持仓提醒是两个不同问题 |

### 3.3 复合场景

复合问题只合并实际命中的场景：

| 用户问题 | MCP 计划 | 不需要调用 |
| --- | --- | --- |
| “我买了什么，今年赚了多少” | `queryHoldingDetail` + `queryProfitAnalyzeSum` | 资产分类、回撤、归因 |
| “今年跑赢大盘了吗，谁在拖累” | `queryProfitAnalyze` + `queryProfitAttribution` | 总资产、资产分类 |
| “我的产品和行业是否集中” | `queryHoldingDetail` + `queryAssetClassify` | 收益、归因 |
| “今天账户怎么样，有什么要关注” | `queryAssetIndex` + `queryHoldingSignal` | 历史收益、归因 |

## 4. 各场景怎样输出

每次输出均由三部分组成：

```text
summary：直接回答当前问题，给出 1～3 个关键事实
业务 section：中性说明下方卡片展示什么，不填诊断值
conclusion：解释这些事实意味着什么，并明确本次判断边界
```

下列 `{字段}` 只是输出位置，只有 MCP 实际返回且校验通过时才能填写。

### 4.1 账户总览场景

数据：`queryAssetsTotal`。

```text
summary：截至{数据日期}，账户总资产为{总资产}，主要由{最大账户类型}构成，共持有{持仓数量}项产品。

业务 section：下方卡片展示账户总资产及账户构成。

conclusion：本次只能判断账户规模和构成；未查询产品结构、区间收益和收益归因，不对此作判断。
```

可输出卡片：ACC-01，或用户明确账户类型对应的账户详情卡；卡片 `data` 为空。

### 4.2 产品持仓场景

数据：`queryHoldingDetail`。

固定计算：

```text
产品数量 = 有效产品记录数
单一产品最大占比 = max(item.percent)
Top 3 产品占比 = 持仓占比最高三项之和
Top 5 产品占比 = 持仓占比最高五项之和
产品集中度 HHI = Σ(item.percent²)
```

```text
summary：账户共持有{产品数量}项产品，最大持仓为{产品名称}、占比{比例}，Top 3 合计占比{比例}。

业务 section：下方卡片展示当前产品持仓明细。

conclusion：持仓主要集中在{头部产品事实}。只有达到已确认的集中度阈值后，才能进一步使用“过度集中”等判断。
```

可输出卡片：ACC-11；卡片 `data` 为空。

### 4.3 资产、地区和行业结构场景

数据：`queryAssetClassify`。

分别对 `fundTypeList`、`assetClassList`、`marketRegionList`、`industryStyleList` 计算最大项、Top N 占比；如规则需要，再计算 HHI。

```text
summary：账户资产主要分布在{主要资产类别}；区域以{主要区域}为主；行业或风格的最大暴露为{主要行业/风格}。

业务 section：下方卡片展示资产类别、市场区域和行业风格分布。

conclusion：当前最明显的结构特征是{有数据支持的主要暴露}。没有正式阈值时只描述结构，不判断是否配置合理。
```

可输出卡片：ACC-12；卡片 `data` 为空。

### 4.4 收益总览场景

数据：`queryProfitAnalyzeSum`。

```text
summary：{诊断周期}账户收益为{收益金额}，收益率为{收益率}；其中{持有收益/已兑现收益等接口已返回事实}。

业务 section：下方卡片展示账户收益总览。

conclusion：本次只能判断赚亏结果；没有查询基准和回撤时，不能判断收益质量或风险水平。
```

可输出卡片：ACC-13-A；卡片 `data` 为空。

### 4.5 收益、超额收益和回撤场景

数据：`queryProfitAnalyze`。

固定判断：

```text
totalYield > 0  → 区间取得正收益
totalYield = 0  → 在状态确认为真实零值时，区间收益为零
totalYield < 0  → 区间发生亏损
excessReturn > 0 → 跑赢所选基准
excessReturn = 0 → 与所选基准持平
excessReturn < 0 → 跑输所选基准
```

```text
summary：{诊断周期}账户收益率为{收益率}，相对{基准}的超额收益为{超额收益}，最大回撤为{最大回撤}。

业务 section：下方卡片展示账户收益及走势。

conclusion：账户在该周期{跑赢/持平/跑输}基准；最大回撤的严重程度只有在阈值或比较标准确认后才能判断。
```

可输出卡片：ACC-13-A 或 ACC-13-B，由用户的收益视角决定；卡片 `data` 为空。

### 4.6 收益时段场景

数据：`queryProfitCalendar`。

```text
summary：在{诊断周期}内，收益最好时段为{时段及收益}，最差时段为{时段及收益}。

业务 section：下方卡片按用户要求展示日、月或年收益明细。

conclusion：收益主要集中在{有证据的时段特征}；不能仅凭单个最好或最差时段推断长期表现。
```

可输出卡片：ACC-14；卡片 `data` 为空。

### 4.7 收益归因场景

数据：`queryProfitAttribution`。

```text
summary：{诊断周期}内，主要收益贡献来自{贡献项及金额}，主要拖累来自{拖累项及金额}。

业务 section：下方卡片展示收益贡献项和拖累项。

conclusion：本期损益主要由{有证据的归因对象}影响。除非同时取得持仓权重，否则不判断该产品对当前账户的风险影响大小。
```

可输出卡片：ACC-15；卡片 `data` 为空。

### 4.8 数据不可用时

```text
summary：当前未能取得回答{当前问题}所需的{数据类型}，暂时无法形成数据判断。

业务 section：仍可按用户意图输出 deferred 卡片。

conclusion：本次不对{缺失范围}作判断，可稍后重试或缩小查询范围。
```

不能用卡片将来可能加载的数据补写 summary 或 conclusion。

## 5. 完整账户诊断场景

只有用户明确提出“全面诊断我的账户”“给账户做一次体检”“从结构、收益和归因整体分析”时，才进入完整场景。

### 5.1 MCP 计划

| 诊断问题 | MCP |
| --- | --- |
| 账户有多少资产、由什么账户构成 | `queryAssetsTotal` |
| 持有哪些产品、产品是否集中 | `queryHoldingDetail` |
| 资产、地区和行业如何分布 | `queryAssetClassify` |
| 收益、超额收益和回撤如何 | `queryProfitAnalyze` |
| 谁贡献收益、谁造成拖累 | `queryProfitAttribution` |

这五个 MCP 是**完整诊断场景**的证据组合，不是所有账户问题的固定调用清单。某项失败时，其他成功结果仍可形成局部诊断，但必须标出缺失范围。

### 5.2 完整诊断输出顺序

```text
数据质量
→ 账户规模
→ 产品结构
→ 资产、地区和行业结构
→ 收益、超额收益和回撤
→ 主要贡献与拖累
→ 综合结论与数据边界
```

输出模板：

```text
summary：本次诊断覆盖{账户范围和周期}。账户规模为{事实}；该周期收益和相对基准表现为{事实}；当前最值得关注的是{最重要的结构或归因事实}。

结构诊断：产品主要集中在{事实}；资产、地区和行业的主要暴露为{事实}。

收益诊断：区间收益为{事实}，超额收益为{事实}，最大回撤为{事实}。

归因诊断：主要贡献来自{事实}，主要拖累来自{事实}。

conclusion：综合来看，账户当前的核心特征是{结构事实 + 收益事实 + 归因事实}；由于{缺失数据或能力边界}，暂不判断{不能判断的事项}。
```

业务 section 根据实际需要选择 ACC-01、ACC-11、ACC-12、ACC-13-A 和 ACC-15；所有卡片保持 `deferred` 且 `data` 为空。卡片数量不反向决定 MCP 调用。

## 6. 数据质量检查

只检查本次实际调用的 MCP：

- 调用是否成功；
- 返回是正常零值、空数据还是不可用；
- 收益是实际值还是估算值；
- 账户范围是否一致；
- 收益、基准和归因周期是否一致；
- 净值日、收益日和持仓日是否足以支持当前判断；
- 当前输出所需的关键字段是否完整。

统一区分：

```text
真实值为 0 ≠ 没有数据
没有数据 ≠ 数据不可用
估算数据 ≠ 实际数据
```

数据质量结论：

```text
complete：本场景所需数据齐全且口径一致
partial：部分数据可用，只输出有证据的局部结论
unavailable：本场景核心数据不可用，不生成业务判断
```

## 7. 不能从现有数据得出的结论

现有 MCP 没有用户 KYC、投资目标、投资期限和风险承受能力，也没有跨基金完整底层证券、费率和基金评价数据。因此不能判断：

- 账户是否适合用户；
- 当前配置是否符合用户目标；
- 跨基金是否重复持有同一底层证券；
- 组合整体风险等级；
- 综合费率是否合理；
- 某只基金质量好坏；
- 是否应该买入、卖出或调仓。

“结构集中”“出现回撤”“某产品造成拖累”是账户事实或规则判断，不等于投资建议。

## 8. 取数依据与待确认项

MCP 取数说明主要位于：

- [`documentation/AI顾问账户卡片与数据.md`](../AI顾问账户卡片与数据.md)：MCP 清单、接口、请求参数、返回字段、数据状态和失败降级；
- [`account-diagnosis/references/mcp-summary-conclusion.md`](../../account-diagnosis/references/mcp-summary-conclusion.md)：最小 MCP 调用、证据边界和 summary/conclusion 规则；
- [`documentation/AI顾问结果输出与组件编排.md`](../AI顾问结果输出与组件编排.md)：按意图选 section、卡片 deferred 规则和最终输出结构。

运行时 MCP Schema 是工具名称、参数、返回结构和错误格式的最终依据。

实施前仍需确认：

1. 完整诊断的默认时间范围和比较基准；
2. `queryAssetClassify.type` 各值的正式语义；
3. 收益、回撤和归因的时间参数如何保持一致；
4. 金额、收益率、净值的单位、精度和正负号；
5. MCP 原始状态到统一数据状态的映射；
6. 持仓产品标识与归因产品代码的映射；
7. 产品、资产、地区、行业集中度阈值；
8. 最大回撤严重程度阈值；
9. MCP 超时、部分成功和重试规则；
10. 现有资料中 ACC-15 `data.dateType` 与“所有卡片 `data` 为空对象”的冲突，需要统一为后者。
