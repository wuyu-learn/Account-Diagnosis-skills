# 账户诊断组件卡片清单

> Agent 速查用：以当前新版页面为准，汇总现有卡片组件。

## 通用卡片结构

本文档中的具体卡片均使用统一的卡片容器。卡片本体只负责声明组件身份、取数方式和组件数据，不负责页面展示顺序及文字表达。

```json
{
  "cardId": "CARD-ID",
  "dataMode": "inline | deferred",
  "data": {}
}
```

| 字段 | 作用 |
| --- | --- |
| `cardId` | 卡片组件及其数据协议的唯一标识，并用于与响应中的展示区块关联 |
| `dataMode` | 数据提供方式：`inline` 表示直接返回数据，`deferred` 表示后续取数 |
| `data` | 传给卡片组件的数据载荷；具体业务字段由对应组件的数据协议定义 |

### Inline 数据

```json
{
  "cardId": "CARD-ID",
  "dataMode": "inline",
  "data": {
    "status": "available",
    "...": "实际组件数据"
  }
}
```

`inline` 模式下，`data` 中直接包含组件渲染所需的真实数据。

### Deferred 取数

```json
{
  "cardId": "CARD-ID",
  "dataMode": "deferred",
  "data": {
    "request": {
      "...": "取数参数"
    }
  }
}
```

`deferred` 模式下，当前响应只提供取数信息，由后续流程获取实际组件数据。

### 结构边界

- `cardId` 只标识组件及其数据协议，不代表数据本身。
- `data` 是卡片组件的输入数据，可视为前端组件的 `props`。
- 标题、解释文字和展示顺序不属于卡片本体。
- `type`、`chartType` 属于旧版的重复描述，不纳入当前通用卡片结构。
- 数据缺失时必须返回明确的状态或空值，不得使用 `0` 或虚构数据代替。
