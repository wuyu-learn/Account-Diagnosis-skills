# 复杂账户诊断理念注入优化计划

计划日期：2026-08-01

计划次序：第二阶段（复杂账户诊断理念注入）

前置计划：[`AI顾问账户诊断重构计划-2026-08-01-01.md`](./AI顾问账户诊断重构计划-2026-08-01-01.md)

执行条件：第一阶段完成账户复杂度路由、固定业务骨架、simple/complex 分流及最终 v2.2 编排后，再实施本计划。

## 1. 当前缺口

[`我的账户诊断理念与逻辑.md`](../优化建议/我的账户诊断理念与逻辑.md) 已经定义了账户诊断思路，但当前 Skill 主要规定路由、取数和输出结构，复杂任务仍只是“读取一份说明后生成 Summary/Conclusion”。缺少四件事：

- 账户顾问在所有任务中应遵守的工作立场；
- 理念在复杂任务中的固定注入位置；
- 理念如何转化为必须执行的诊断步骤；
- 如何判断模型输出的是账户诊断，而不是多项数据摘要。

因此，本次优化不是增加更多理念文字，而是把理念变成复杂任务的执行约束。

## 2. 优化目标

先在根 `SKILL.md` 固化账户顾问的工作立场；当 `taskComplexity = complex` 时，再在生成 Summary/Conclusion 前注入账户诊断理念，要求模型完成：

```text
先检查证据质量
→ 从单品转向组合视角
→ 评价收益、超额收益和回撤
→ 定位主要贡献和拖累
→ 建立结构与收益来源之间的关系
→ 确定最值得关注的问题
→ 明确数据和能力边界
```

简单任务不注入这套完整诊断链，仍只直接回答明确问题。

## 3. 账户顾问的工作立场

这里的“人格”不是语气人设，而是 Skill 面对用户时的职责边界。应放在 `account-diagnosis/SKILL.md` 的入口角色说明之后、资源和工作流之前，使 simple 和 complex 两条分支都能读取。

建议写入：

```markdown
## 账户顾问的工作立场

本 Skill 的职责是帮助用户看清账户，而不只是展示账户数据。

- 不是数据播报器：除呈现事实外，还要说明这些事实与用户当前问题有什么关系；
- 不是产品销售：不把账户诊断自然导向产品推荐；
- 不替用户决策：缺少 KYC、投资目标和风险承受能力时，不给出适配性、买卖或调仓结论；
- simple 任务直接回答局部问题，不扩大为账户整体评价；
- complex 任务从组合视角建立结构、表现和归因之间的关系，并指出最值得关注的问题；
- 数据不足时明确判断边界，不用推测填补证据；
- 表达保持清楚、克制、有依据，既不制造焦虑，也不回避已经发现的问题；
- followUp 提供可选的继续诊断方向，不替用户作决定。
```

这段内容只定义“以什么立场服务用户”。simple 如何回答由 `references/simple-summary.md` 负责，complex 如何形成诊断由 `references/complex-diagnosis.md` 负责。

## 4. 注入位置

```text
account-diagnosis/SKILL.md
→ 所有账户任务先遵守账户顾问的工作立场

上游 Planner
→ 确认 taskComplexity = complex
→ 生成卡片计划

代码
→ 生成固定业务骨架

MCP 取数与数据质量检查
→ 形成已校验的诊断证据

复杂诊断大模型任务
→ 注入账户诊断理念
→ 输入 originalQuery、账户计划和已校验证据
→ 生成 Summary + Conclusion

代码
→ 合并并校验固定 v2.2 结果
```

工作立场约束所有账户任务；完整账户诊断理念只注入复杂诊断大模型任务。二者都不写入上游账户计划、业务 Section 或最终 JSON。

## 5. 注入内容

将理念收敛为以下固定诊断约束：

### 5.1 诊断对象

账户诊断关注“这些产品组合在一起意味着什么”，不是逐只评价产品。

### 5.2 证据顺序

1. 明确账户范围、数据日期和诊断周期；
2. 检查 MCP 成功、空数据、真实零值、估算值和口径一致性；
3. 分析产品、资产、地区和行业结构；
4. 评价绝对收益、相对基准表现和最大回撤；
5. 通过归因定位主要贡献和拖累；
6. 只有账户范围、周期和对象标识一致时，才建立跨维度关系。

### 5.3 诊断判断

复杂任务必须给出以下两种结果之一：

```text
有充分证据
→ 形成“结构事实 + 表现事实 + 归因事实”的关系判断
→ 给出一至三个关注点及优先级

证据不足
→ 明确哪些维度可以判断
→ 明确哪些关系无法建立及原因
```

不能只罗列总资产、持仓、收益和归因数字后称为“综合诊断”。

### 5.4 能力边界

没有 KYC、客户目标、投资期限和风险承受能力时，不判断：

- 账户是否适合用户；
- 当前配置是否合理；
- 是否应该买入、卖出或调仓；
- 某只基金本身质量好坏。

## 6. 两类复杂任务

### 完整账户诊断

适用于“我的账户怎么样”“给账户做一次体检”等整体问题。

默认覆盖账户范围、产品结构、资产/地区/行业结构、收益质量和收益归因；某项证据不可用时保留其他局部诊断，并说明缺失范围。

### 关系型诊断

适用于“哪些重仓产品是主要拖累”“持仓结构为什么导致收益不好”等问题。

只取得建立该关系所需的最少证据，不因为任务复杂就固定调用全部 MCP。例如“重仓产品是否造成拖累”只需要持仓和同周期产品归因证据。

该分类只用于复杂诊断任务内部选择诊断路径，不新增账户 Planner 字段，也不改变最终输出协议。

## 7. 输出要求

### Summary

回答：本次诊断覆盖什么、发生了什么、最重要的发现是什么。

```text
账户范围和周期
+ 核心表现
+ 第一优先级发现及证据
```

### Conclusion

回答：这些事实组合在一起意味着什么、先关注什么、当前不能判断什么。

```text
跨维度关系判断
+ 关注点优先级
+ 数据或能力边界
```

Conclusion 不重复数字清单，不引入新事实，不直接生成投资建议。

## 9. 验证场景

| 用户问题 | 必须体现的诊断逻辑 |
| --- | --- |
| “我的账户怎么样” | 完整诊断链、核心问题和优先级 |
| “哪些重仓产品是主要拖累” | 持仓权重与同周期产品归因的关系 |
| “持仓结构为什么导致收益不好” | 结构、表现和归因之间的证据关系 |
| “我的账户风险是不是太高” | 报告已有回撤和结构事实，但说明缺少正式风险阈值/KYC |
| MCP 部分失败 | 只形成可验证的局部诊断，并明确缺失维度 |

验收标准：

- complex 输出至少形成一个有证据的跨维度关系；证据不足时必须明确无法建立关系；
- 输出包含问题优先级，而不是并列罗列所有发现；
- 所有判断可追溯到本次 MCP 证据；
- 不使用 deferred 卡片未来可能加载的数据；
- 不越界形成适配性、买卖或调仓建议；
- 回答能够说明事实与用户问题的关系，不退化为数据播报或产品推荐；
- 表达清楚、克制、有依据，followUp 只是可选方向；
- simple 行为、卡片结构和最终 v2.2 六个顶层字段完全不变。
