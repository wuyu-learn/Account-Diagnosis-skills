# 卡片标识符参数填值机制补全计划

计划日期：2026-08-03

计划次序：第四阶段（卡片标识符参数填值机制）

前置计划：[`用户问题与卡片组合规则修改计划-2026-08-01-03.md`](./用户问题与卡片组合规则修改计划-2026-08-01-03.md)

## 1. 当前缺口

用户问"某只基金某一笔份额（如定投计划）的持仓明细"时，ACC-03 输出 `data: {}`，deferred 卡片无法定位到那一笔。表面是"用户没给可选参数就留空"（`account-card-routing.md:188`），真正原因是架构链路 + 标识符来源，不是规则措辞。

## 2. 标识符与卡片粒度

卡片按粒度分两层，标识符不同：

| 层级 | 卡片 | 标识 | 来源 |
| --- | --- | --- | --- |
| 产品级（跨类型通用） | ACC-19 | `productId` | 上游/实体透传（产品代码，非基金代码） |
| 份额级（类型专属） | ACC-03/05/06/08/10 | `serialNo`/`uri` | MCP（`queryHoldingDetail`） |

份额是人工定义的单位，比渠道更细（产品→渠道→份额）；`serialNo`/`uri` 定位某一笔份额。账户级（ACC-01/02/04/07/09）不携带标识符。

## 3. 根因

- `card.data ≡ params`：`build_result_skeleton.py:203` 直接 `"data": params`，`compose_result.py:76-144` 只校验不注入。
- `serialNo`/`uri` 不在 entities 槽位（`SKILL.md:54-61`），用户说不出、entities 带不了。
- Planner 在 MCP 之前，且不调用 MCP、只用用户实体（`account-route-planner.md:23,51`）。决策 params 时份额标识还不存在。
- MCP 数据默认禁止入卡（`mcp-evidence.md:71`）。

对比 ACC-15 的 `dateType`：值来自用户语言，plan 阶段就能填；份额标识来自 MCP，plan 阶段拿不到，所以不能照 `dateType` 模式，必须 MCP 后回填。

## 4. 解决方案

两条轨道，对应两层粒度：

- **产品级 `productId`（轻）**：`productId` 是产品代码（不是基金代码），上游/实体已提供时 Planner 透传到 `params.productId`，不自行换算；走正常 plan→骨架流程，无需回填脚本。
- **份额级 `serialNo`/`uri`（重）**：新增"MCP 后回填"阶段，取数路径为

  ```text
  queryHoldingDetail（持仓明细）
  → 取得该产品按份额拆开的各笔，每笔带 serialNo/uri + 渠道标识
  → 按用户指定的份额匹配到那一笔
  → 取出 serialNo/uri 注入对应 deferred 卡片 data
  ```

  在 `compose` 之前完成。`serialNo`/`uri` 作为份额定位标识，是"MCP 不入卡"的窄口子例外，其余 MCP 字段仍不入卡。`compose_result.py` 的 `allowedParams` 已支持，无需改校验。
