# Complex Diagnosis

仅在主路径代码返回 `responseMode=diagnostic` 时读取。一次生成
`summaryNarrative + conclusionNarrative`，不生成业务 Section、卡片或最终 JSON。

## 输入边界

必须使用：原始问题、只读账户计划、本次 MCP 已校验证据及其账户范围、周期、对象
标识和可用状态。不得使用 deferred 卡片未来可能加载的数据，不得把 MCP 原始响应
直接改写成结论。

## 两类诊断

### 完整账户诊断

仅适用于用户明确要求账户诊断、体检、全面分析或找主要问题。依次检查账户规模、
产品和资产结构、收益/基准/回撤、贡献与拖累。通常需要资产总览、持仓、分类、收益
和归因证据，但仍以完成本次判断的最少 MCP 为准。

### 关系诊断

只取得目标关系所需证据：

| 目标关系 | 最少证据 |
| --- | --- |
| 重仓是否为主要拖累 | 同范围同周期的持仓权重 + 产品归因 |
| 行业暴露是否造成拖累 | 行业结构 + 同周期行业归因 |
| 跑输基准的原因 | 收益/基准表现 + 同周期归因 |

## 诊断规则

MCP 返回并完成数据质量检查后：

1. 明确账户范围、数据日期和周期；
2. 区分可用、部分可用、不可用、真实零值和估算值；
3. 把单品清单转换为组合结构；
4. 评价绝对收益、相对基准表现和最大回撤；
5. 定位主要贡献与拖累；
6. 仅在账户范围、周期和对象标识一致时建立关系；
7. 保留一至三个发现并排序；
8. 说明数据和能力边界。

优先级：主要拖累与头部持仓/暴露重合 > 跑输或回撤但原因未完全定位 > 收益依赖
少数产品/暴露 > 只有结构特征且尚无收益影响。

证据充分时至少形成一个跨维度关系判断；证据不足时明确哪些局部事实成立、哪些关系无法建立以及原因。
只有结构集中而没有负归因时，只能认定集中，不能认定已经
造成问题。

没有 KYC、投资目标、期限和风险承受能力时，不判断账户是否适合用户，不给出买卖、
调仓或产品推荐。

## 输出

```json
{
  "summaryNarrative": "范围和周期 + 核心表现 + 第一优先级发现及证据。",
  "conclusionNarrative": "跨维度判断 + 关注优先级 + 当前不能判断的边界。",
  "followUp": []
}
```

Summary 回答“发生了什么、最重要的发现是什么”；Conclusion 回答“事实组合起来意味
着什么、先关注什么、现在不能判断什么”。Conclusion 不重复数字清单、不引入新事实。
