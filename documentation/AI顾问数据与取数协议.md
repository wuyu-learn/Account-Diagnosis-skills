# AI 顾问数据与取数协议

本文档作为项目中数据相关内容的统一归档入口。后续涉及以下主题的资料均在本文档中补充和维护，不再单独建立同类文档：

本文档不定义完整响应骨架、内容顺序或页面编排。

## 数据模式

卡片通过 `dataMode` 声明数据的提供方式：

| 模式 | 含义 |
| --- | --- |
| `inline` | 数据直接包含在当前响应中，前端收到后立即渲染 |
| `deferred` | 当前响应只提供取数信息，前端随后调用接口获取数据 |

### Inline

```json
{
  "cardId": "CARD-ID",
  "dataMode": "inline",
  "data": {
    "status": "available"
  }
}
```

- `data` 必须来自真实数据源，不得由 AI 编造。
- 数据缺失时返回明确状态，不使用示例值填充。
- 前端无需再次调用卡片取数接口。

### Deferred

```json
{
  "cardId": "CARD-ID",
  "dataMode": "deferred",
  "data": {
    "request": {
      "card_id": "CARD-ID",
      "period": "latest"
    }
  }
}
```

基本流程：

```text
生成卡片描述
→ 返回 deferred 取数参数
→ 前端调用卡片接口
→ 接口返回卡片数据
→ 前端渲染
```

- 取数参数必须包含接口执行所需的上下文。
- 参数名称和必填项由正式接口契约确定。
- 取数失败或超时时不得生成虚假数据代替。

## 数据状态

数据模式与数据状态相互独立。无论使用哪种模式，数据都可能处于以下状态：

| 状态 | 含义 |
| --- | --- |
| `available` | 数据正常可用 |
| `zero` | 数据正常，实际数值为 0 |
| `empty` | 当前统计范围内没有数据 |
| `unavailable` | 数据缺失、接口异常或暂不可用 |
| `estimated` | 当前数据为估算值 |
| `mixed` | 部分数据已确认，部分仍为估算值 |
| `real` | 数据已经确认 |

必须区分：

```text
真实值为 0 ≠ 没有数据
没有数据 ≠ 数据不可用
估算数据 ≠ 已确认数据
```

## 待统一项

现有资料中，deferred 取数信息存在两种表达：

```json
{
  "data": {
    "request": {}
  }
}
```

和：

```json
{
  "dataQuery": {
    "api": "",
    "params": {}
  }
}
```

后续需要确定：

1. 取数信息使用 `data.request` 还是 `dataQuery`。
2. 接口地址由响应返回，还是由前端根据 `cardId` 映射。
3. 通用参数、业务参数和必填参数的命名方式。
4. 取数失败时隐藏卡片、显示错误卡片还是统一空态。
5. 字段统一使用 `snake_case` 还是 `camelCase`。
