# AI 顾问整体架构

## 文档定位

本文档说明 AI 顾问系统的上层处理链路，以及账户诊断相关 Skills 在整体系统中的位置。账户诊断只是全局场景分发后的一个业务分支。

## 全局三段式流水线

```text
用户查询
→ Global Phase A：路由与实体抽取
→ Global Phase B：按场景分发及业务域处理
→ Global Phase C：结果聚合与编排
→ v2.2 统一响应
```

### Global Phase A：路由与实体抽取

通过语义判断完成：

- 识别一个或多个业务场景。
- 将复合问题拆成可独立处理的 `subQuery`。
- 为场景分配权重并确定主场景。
- 提取基金、基金经理、基金公司、市场主题和策略等业务实体。

典型输出：

```json
{
  "scenes": [
    {
      "scene": "问账户",
      "weight": 0.9,
      "subQuery": "我的账户今年收益怎么样"
    }
  ],
  "entities": {},
  "primaryScene": "问账户",
  "isMultiScene": false
}
```

LLM 负责语义识别；代码负责补齐缺失值、规范字段、计算多场景标识及确认主场景。

### Global Phase B：场景分发及业务域处理

根据 `scenes[].scene` 将子问题分发给对应业务域：

```text
Global Phase B
├── 问账户
├── 问基金
├── 问市场
├── 问策略
└── 问投教
```

多个场景可以并行处理。每个业务域负责自己的意图分类、业务规则、数据获取和局部结果生成。

### Global Phase C：结果聚合与编排

接收各业务域处理结果并生成完整响应：

- 按业务顺序合并内容区块。
- 合并并去重卡片。
- 建立 section 与 card 的关联。
- 生成跨场景概要、结论和后续问题。
- 添加风险提示。
- 输出统一的 v2.2 JSON。

`result-composer` 属于这一阶段。

## 账户诊断的位置

账户诊断位于 Global Phase B 的“问账户”业务分支：

```text
Global Phase A：route-extract
        ↓
Global Phase B：场景分发
        ↓
问账户业务分支
└── account-diagnosis（账户总控入口）
    ├── 账户意图识别模块
    ├── 账户领域内部模块
    │   ├── 资产总览
    │   ├── 持仓结构
    │   ├── 收益表现
    │   ├── 收益归因
    │   └── 自选基金估值
    ├── 生成卡片取数计划
    ├── 获取账户卡片数据
    └── 结果编排模块
        ↓
Global Phase C：统一响应
        ↓
统一响应
```

账户域内部不要继续使用 Global Phase A、B、C 命名，避免与上层阶段混淆。账户内部步骤可以使用：

```text
Account Step 1：账户意图识别
Account Step 2：卡片选择与取数计划
Account Step 3：账户数据获取
```

## LLM 与代码的职责

适合由 LLM 完成：

- 场景和意图的语义判断
- 复合问题拆分
- 结果摘要和分析文字
- 跨场景内容衔接
- 后续问题生成

适合由代码完成：

- 字段规范化
- 权重和主场景兜底
- Agent 调度
- JSON 拼接
- 卡片去重
- 引用完整性检查
- Schema 校验

基本原则：

```text
LLM 负责理解与表达
代码负责调度、拼接与校验
```

## 请求上下文

用户身份、会话和鉴权信息不属于语义实体，不应由 LLM 从用户问题中提取或生成。

建议由系统入口提供独立请求上下文：

```json
{
  "requestContext": {
    "userId": "USER-ID",
    "sessionId": "SESSION-ID"
  },
  "query": "我的账户今年收益怎么样"
}
```

处理要求：

- `requestContext` 由可信系统层注入。
- 路由及业务 Skills 只能原样透传，不得生成或修改身份字段。
- 数据获取层使用请求上下文确定账户数据范围。
- 最终对外响应不应返回内部鉴权信息。

## 当前项目边界

当前项目主要覆盖：

- Global Phase A 的场景路由。
- “问账户”业务分支的总控调度、意图识别、卡片选择和取数规则。
- Global Phase C 的结果编排能力。

当前项目不负责其他业务域的具体处理逻辑，也不负责用户认证、权限校验、接口网关或前端组件实现。
